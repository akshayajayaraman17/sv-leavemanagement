# 17. AI Design Generation Prompts

One prompt per screen, for use with an AI design tool to produce improved mockups. Every prompt shares the same **Visual Direction** footer (given once below, then referenced) to guarantee cross-screen consistency, per Part 19 of the source brief. Business-rule/state/accessibility content is pulled directly from `05_PAGE_BY_PAGE_SPECIFICATION.md` — nothing here is invented independently of that spec.

## Shared Visual Direction (applies to every prompt below)
> Use the existing application's visual identity as the starting point: DM Sans typeface, the `C` color palette (`#1D9E75` green primary, `#378ADD` blue, `#BA7517` amber, `#7F77DD` purple, `#A32D2D` red, all on a warm off-white `#f5f4f0` background), flat 12px-radius cards with hairline borders, 8px-radius buttons/inputs, no drop shadows except a new subtle elevation reserved for modals/toasts. Improve: hierarchy, spacing consistency (adopt the 4px spacing scale from `13_DESIGN_SYSTEM.md`), a visible focus ring on every input (currently missing app-wide), one unified status-badge component (currently 3 divergent implementations), and information density on data-heavy admin screens. Do NOT introduce a new color palette, a card-replacement layout primitive, or a component library — extend what exists. Do NOT redesign unrelated modules while working on one screen.

### DESIGN GENERATION PROMPT — Login
**User**: Unauthenticated visitor. **Objective**: Sign in, or recover a forgotten password via OTP. **IA**: Single card, no nav chrome. **Layout**: Centered card, ~360px wide, vertically centered on the `bgSec` page background. **Components**: `card`, `Field`, primary button, 4-step dot progress indicator for the recovery subflow. **Fields**: Email, Password (sign-in); Email, OTP, New Password, Confirm Password (recovery, one step visible at a time). **Actions**: Sign In; Forgot Password; Send Code; Verify; Reset Password. **States**: Loading (button spinner), Empty (n/a), Error (inline text under the form), Success (immediate redirect), Disabled (submit while in-flight), Permission denied (n/a). **Interaction**: Recovery flow replaces the sign-in form in place, step indicator updates; add a live password-strength meter as New Password is typed (currently only a bare length check surfaces on submit). **Business Rules**: password ≥8 chars (RULE-SEC-001). **Responsive**: identical single-card layout at every width (no nav chrome to reflow). **Accessibility**: visible focus ring on every input (new), `aria-live="polite"` on the inline error region (new).

### DESIGN GENERATION PROMPT — Force Password Change
**User**: Newly-onboarded employee, first login. **Objective**: Set a private password before reaching the app. **IA**: Single full-screen card, no nav chrome, no escape except Sign Out. **Layout**: Matches Login's card style; explanatory copy above the form. **Components**: `card`, `Field`, primary + ghost (sign-out) buttons. **Fields**: New Password, Confirm Password. **Actions**: Save; Sign Out. **States**: as Login. **Interaction**: add a live match indicator as Confirm is typed, and add a "new ≠ temporary password" check for parity with Profile's password flow. **Business Rules**: RULE-EMP-001, RULE-SEC-001/002. **Responsive/Accessibility**: as Login.

### DESIGN GENERATION PROMPT — Dashboard
**User**: Any authenticated employee. **Objective**: See balance/upcoming events/recent activity at a glance and act on the most common next step. **IA**: root/default screen. **Layout**: profile summary → 2-/4-col leave-balance grid with per-tile usage bars → This Month (holidays/birthdays) → pending comp-off → recent leaves, single scrolling column, sidebar/bottomnav present. **Components**: `card` ×N, `Avatar`, progress bar, `Badge`. **Fields**: none (read-only). **Actions**: **new** — add a primary "Apply Leave" / "Check In" quick-action row near the top (the current screen has zero actionable buttons, the top cross-page UX problem). **States**: Loading (spinner while 5 parallel fetches resolve), Empty (per-section, e.g. no holidays this month), Error (per-section retry — currently missing, add it), Success (n/a), Disabled (n/a), Permission (identical for all roles). **Business Rules**: RULE-LV-014/015 (balance math feeds the tiles). **Responsive**: `.balance-grid` 2-col mobile → 4-col desktop. **Accessibility**: progress bars need a text-equivalent value, not color/fill alone.

### DESIGN GENERATION PROMPT — Notifications
**User**: any role; managers/admins see an extra pinned "N pending your approval" banner. **Objective**: See what changed since last visit. **IA**: single feed. **Layout**: pinned banner (conditional) → reverse-chronological list. **Components**: `card` per item. **Actions**: none currently (read-only) — consider making items clickable through to their source screen. **States**: Loading, Empty (`Empty` placeholder), Error (no retry today — add one), Success/Disabled/Permission n/a. **Interaction — new**: add a lightweight "new since last visit" visual distinction (even client-only) since the current feed has no read/unread state at all. **Business Rules**: synthesized from 5 tables client-side, no dedicated notifications table. **Responsive**: single column always. **Accessibility**: no `aria-live` currently — add it if items begin appearing without a full page reload.

### DESIGN GENERATION PROMPT — Attendance
**User**: any role, self-service. **Objective**: Check in/out accurately and resolve a missed checkout without friction. **IA**: single screen, conditional regularization sub-form. **Layout**: primary Check In/Out control + live hours readout → 5-day week strip → punch log → missing-checkout warning (conditional) → regularization form (conditional). **Components**: large primary button, `card` rows, amber/red warning card. **Fields**: Proposed Check-Out Time, Reason (regularization only). **Actions**: Check In, Check Out, Check In Again, Regularize, Submit. **States**: Loading, Empty (no punches yet today), Error — **critical, must redesign**: geolocation-denied currently hard-blocks the entire screen with no fallback; design a manual location/notes entry path for this case. Success (toast + immediate hours update), Disabled (while a geolocation/DB call is in flight), Permission (n/a, no role branching). **Business Rules**: RULE-AT-001 through AT-009. **Responsive**: week strip should reflow to a wider row at desktop rather than staying phone-width. **Accessibility**: ensure the manual-fallback path (new) is fully keyboard-operable from the start.

### DESIGN GENERATION PROMPT — Timesheet
**User**: any role. **Objective**: Log task hours per day and submit by the weekly deadline without confusion about why the form is locked. **IA**: week navigator + 5 day-cards. **Layout**: week selector → Mon-Fri day cards with inline entry forms → weekly total vs. 40h target → lock/deadline banner (conditional) → Submit. **Components**: `card` per day, `TsBadge` (recommend merging into the unified `StatusBadge`, see `13_DESIGN_SYSTEM.md`), inline entry form. **Fields**: Jira Issue Key (conditional), Project, Task Description, Hours. **Actions**: Add Entry, Submit, Request Late Submission. **States**: Loading, Empty (day with no entries), Error (inline per-day, pre-submit — already good, keep this pattern), Success, Disabled (Submit until valid), Permission (n/a). **Interaction — new**: fire a toast the instant the Friday deadline passes if the tab is open, and visually distinguish "locked" (disabled, tooltip-explained) from a merely-empty day rather than just letting Add/Submit silently no-op. **Business Rules**: RULE-TS-001 through TS-010. **Responsive**: day cards can go 2-wide at tablet, full week visible at desktop. **Accessibility**: standard form semantics + focus ring.

### DESIGN GENERATION PROMPT — Apply Leave
**User**: any role. **Objective**: Request time off with clear balance/date/approver context before committing. **IA**: single form. **Layout**: approver preview card → leave-type dropdown (live balance) → date range + Half Day checkbox → real-time working-days/balance banner → reason → conditional certificate upload → Submit. **Components**: `card`, `Field`, color-coded live banner, dropzone (make keyboard-operable). **Fields**: Leave Type, From Date, To Date, Half Day, Reason, Medical Certificate (sick only). **Actions**: Submit. **States**: Loading, Error (friendly overlap message — keep this pattern, extend the friendly-message approach to Apply Comp Off too), Success (toast + reset), Disabled (submit while invalid/submitting), Permission (n/a). **Interaction — critical redesign target**: when Half Day is checked, disable/clear the End Date field or show an explicit inline warning — currently a multi-day range + Half Day silently collapses to 0.5 days with zero warning. **Business Rules**: RULE-LV-001 through LV-009. **Responsive**: `.form-grid-2` for date fields at desktop. **Accessibility**: certificate dropzone must be keyboard-operable (currently a plain `<div onClick>`).

### DESIGN GENERATION PROMPT — Apply Comp Off
**User**: any role. **Objective**: Request comp-off credit for a verified worked day. **IA**: single form. **Layout**: policy explainer → worked-date picker with live validation chain → attendance-verified summary → avail-by date → reason → Submit. **Components**: `card`, `Field`, real-time validation/summary banner. **Fields**: Worked Date, Date to Avail Comp-Off, Reason. **Actions**: Submit. **States**: as Apply Leave. **Interaction — critical redesign target**: the "Date to Avail Comp-Off" field is currently cosmetic (validated, then discarded before the API call) — either wire it to a real, enforced `avail_by_date` or remove the field and its copy entirely so the UI stops implying an unenforced rule. **Business Rules**: RULE-CO-001 through CO-008. **Responsive/Accessibility**: as Apply Leave.

### DESIGN GENERATION PROMPT — My Leaves
**User**: any role, own history only. **Objective**: Review past requests, see decisions, cancel if eligible. **IA**: 2 sub-tabs (Leave Requests / Comp Off). **Layout**: sub-tab switcher → reverse-chronological card list. **Components**: `card`, `Badge`, conditional Cancel button, certificate link. **Actions**: Cancel (conditional). **States**: Loading, Empty, Error (add retry), Success (cancel → status updates), Disabled (Cancel absent, not just disabled, when ineligible), Permission (n/a). **Interaction — new**: add year/status filters as history grows — currently no filtering or pagination exists at all. **Business Rules**: RULE-LV-012/013, RULE-CO-009/010. **Responsive**: consider a 2-column card grid at desktop rather than staying single-column at every width. **Accessibility**: standard.

### DESIGN GENERATION PROMPT — Team Calendar
**User**: any role. **Objective**: See who's out, when, without exposing private request detail. **IA**: month grid. **Layout**: prev/next/Today nav → Monday-first month grid with holiday highlighting and per-employee leave chips (≤3/day + "+N more"). **Components**: `card` day cells, colored chips. **Actions — new**: make "+N more" open a day-detail popover listing full names (currently static dead text). **States**: Loading, Empty (month with nothing), Error, Success/Disabled/Permission n/a (identical for all roles by RPC design). **Business Rules**: `get_team_calendar()` never exposes reason/certificate — preserve this in any redesign. **Responsive**: introduce an actual tablet-width grid treatment, not just mobile-narrow or full-desktop. **Accessibility**: the new day-detail popover must be keyboard-operable and dismissible via Escape.

### DESIGN GENERATION PROMPT — Approvals
**User**: manager, admin. **Objective**: Clear a mixed approval queue quickly with full decision context. **IA**: 4 sub-tabs (Comp Off / Leave Requests / Timesheets / Regularizations). **Layout**: sub-tab switcher → bulk-select header → per-item cards (timesheets expandable to entry-level detail). **Components**: `card`, expandable entry list, certificate-view link, bulk checkbox row. **Fields**: Bulk Reject Reason. **Actions**: Approve/Reject (per-row and bulk), Select All, View Certificate, Expand Entries. **States**: Loading (per sub-tab), Empty ("Nothing pending" per sub-tab), Error (partial-bulk-failure reporting — already a strength, keep it explicit), Success, Disabled (Reject until reason typed where required), Permission (manager sees own-`approver_id` only; admin sees all — same UI, different dataset). **Interaction — new**: allow per-item reason override within a bulk-reject batch instead of one shared reason for every item. **Business Rules**: RULE-LV-010/011, RULE-TS-008. **Responsive**: this is a strong candidate for an actual `<table>` or dense list at desktop width (currently cards at every width, unusually low-density for how data-heavy this screen is). **Accessibility**: standard, checkboxes/buttons already native.

### DESIGN GENERATION PROMPT — Team (List)
**User**: manager, admin. **Objective**: Find an employee record fast. **IA**: flat searchable list. **Layout**: search box → employee card list. **Components**: `card`, `Avatar`, active/role badges. **Fields**: Search (name/dept/designation/code). **Actions**: click row → detail. **States**: Loading, Empty (no search matches), Error, Success/Disabled/Permission n/a. **Interaction — critical redesign target**: convert the row from a plain `<div onClick>` to a real `<button>`/`role="button"` with `tabIndex`+`onKeyDown` — currently completely unreachable by keyboard, a confirmed WCAG failure. **Business Rules**: salary intentionally never shown here. **Responsive**: standard single/wide-list reflow. **Accessibility**: this screen's #1 priority — see Interaction above.

### DESIGN GENERATION PROMPT — Team Employee Detail
**User**: manager, admin. **Objective**: Review or (admin) edit one employee's full record in context. **IA**: back header + 4-5 in-page tabs. **Layout**: back header → tab switcher → tab content reusing the same card-list patterns as self-service screens. **Components**: `card`, `Field` (edit mode), `Badge`, `Confirm` (last-admin block). **Fields**: Employee Code, Joining Date (admin edit). **Actions**: Edit, Save, Cancel. **States**: Loading (per tab), Empty (per tab), Error, Success, Disabled (Save blocked by last-admin guard), Permission (non-admin managers see read-only, no Salary tab at all). **Business Rules**: RULE-EMP-005 (duplicated guard — flag in any redesign that this should ideally become a single shared component/hook, not a design-only fix). **Responsive**: as the equivalent self-service screens. **Accessibility**: standard.

### DESIGN GENERATION PROMPT — Admin Employees
**User**: admin. **Objective**: Manage the roster from one list. **IA**: search + list + header actions. **Layout**: search → + Add Employee / Bulk Add buttons → employee card list with inline row actions. **Components**: `card`, `Avatar`, badges, `Confirm` (deactivate). **Fields**: Search. **Actions**: + Add Employee, Bulk Add, Edit, Add/Remove Leaves, Deactivate. **States**: Loading, Empty, Error, Success, Disabled (deactivate blocked for last active admin), Permission (admin-only). **Interaction — new**: add a direct "Reactivate" action on inactive rows (currently requires opening the full edit form). **Business Rules**: RULE-EMP-005. **Responsive — redesign target**: this is the single best candidate in the app for a genuine `<table>` at desktop width (≥1100px), given both row count and column-worthy fields (code/name/dept/designation/role/status) — the current card-list-at-every-width choice is the least space-efficient anywhere in the app. **Accessibility**: row actions are already real buttons — no gap here (unlike Team's list).

### DESIGN GENERATION PROMPT — Admin Add/Edit Employee
**User**: admin. **Objective**: Create or fully edit one employee record (details, salary, approvers, leave). **IA**: back header + in-page tabs, one shared Save. **Layout**: tab switcher → tab-specific form → single bottom Save. **Components**: `card`, `Field`, tab switcher, `Confirm` (admin-grant). **Fields**: full Details/Salary/Approvers/Leave/Comp-Off field sets per `05_PAGE_BY_PAGE_SPECIFICATION.md` Page 15 §13. **Actions**: Save, Cancel, per-approver Remove, Comp-Off Grant. **States**: Loading (edit mode), Error, Success, Disabled (submit / last-admin-demotion block), Permission (admin-only). **Interaction — new**: add a short inline note explaining why Employee Code becomes read-only after creation (currently unexplained). **Business Rules**: RULE-EMP-003 through EMP-006/010, RULE-CO-011. **Responsive**: `.form-grid-2`/`.form-grid-3` at desktop for Details/Salary. **Accessibility**: standard, plus focus ring.

### DESIGN GENERATION PROMPT — Admin Bulk Add
**User**: admin. **Objective**: Onboard many employees from one CSV upload. **IA**: 3-step wizard (Upload → Preview → Results). **Layout**: step-appropriate single-column content; per-row validation table at Preview; results + CSV export at Results. **Components**: dropzone, `<table>` (already correct choice here, keep it), progress indicator. **Fields**: Password Mode, Shared Password (conditional), full CSV column set. **Actions**: Download Template, Upload, Create Employees, Export Results, Done. **States**: Loading (per-row sequential progress), Empty, Error (inline per-row + Results summary counts — already a strength), Success, Disabled, Permission (admin-only). **Interaction — critical redesign target**: make the upload dropzone keyboard-operable, and add a per-row masked/copy-button treatment for the plaintext temp passwords in the Results table instead of raw selectable text. **Business Rules**: RULE-EMP-007/008. **Responsive**: the two `<table>`s are the right call at every width here — do not convert to cards. **Accessibility**: dropzone keyboard support is the top priority for this screen.

### DESIGN GENERATION PROMPT — Admin Holidays
**User**: admin. **Objective**: Keep the company holiday calendar current. **IA**: add-form + list. **Layout**: date+name form → flat holiday list with per-row Remove. **Components**: `card`, `Field`, `Confirm`. **Fields**: Holiday Date, Name. **Actions**: Add, Remove. **States**: Loading, Empty, Error (duplicate-date), Success, Disabled, Permission (admin-only). **Interaction — new**: add a "copy last year's holidays" shortcut or CSV import (reusing the Bulk Add pattern) — currently every year is entered one row at a time. **Business Rules**: feeds RULE-LV-001, RULE-CO-002, Team Calendar, Dashboard. **Responsive/Accessibility**: standard, low complexity screen.

### DESIGN GENERATION PROMPT — Admin Audit Log
**User**: admin. **Objective**: Investigate a specific salary/leave-adjustment/role-change event. **IA**: flat reverse-chronological list. **Layout**: single list, diff-style "field: old → new" summaries. **Components**: `card` per entry. **States**: Loading, Empty, Error, Success/Disabled n/a, Permission (admin-only). **Interaction — critical redesign target**: add a visible on-page caveat stating exactly what this log covers (salary/leave-adjustment/role-change only) and what it doesn't (approvals, employee lifecycle, holiday CRUD, Jira connects) — currently the scope is entirely undocumented on the page itself, risking a false sense of completeness during an actual investigation. Longer-term, add actor/date/action-type filters as volume grows. **Business Rules**: RULE-EMP-006/009. **Responsive/Accessibility**: standard.

### DESIGN GENERATION PROMPT — Admin Export
**User**: admin. **Objective**: Get roster/leave/attendance data out as CSV. **IA**: 3 single-purpose cards. **Layout**: Employee Roster / Leave Requests / Attendance cards, each with a description + Export button. **Components**: `card` ×3. **Actions**: Export (×3). **States**: Loading (per-export), Empty (n/a), Error, Success (immediate download), Disabled (while exporting), Permission (admin-only). **Interaction — critical redesign target**: surface the Attendance export's silent 1,000-row cap directly in that card's copy, and add basic date-range filtering to all three exports — currently none exist, and Leave Requests always exports the entire table. **Business Rules**: none beyond the RLS `is_admin()` gate. **Responsive**: 3 cards stack mobile, row or grid at desktop. **Accessibility**: standard.

### DESIGN GENERATION PROMPT — Jira Settings
**User**: any role. **Objective**: Connect a personal Jira account for worklog sync. **IA**: single form + conditional connected-summary. **Layout**: explainer → form → connected-account card (conditional) + Disconnect. **Components**: `card`, `Field`. **Fields**: Jira Site URL, Jira Email, Jira API Token. **Actions**: Save/Update, Disconnect. **States**: Loading, Empty (not-yet-connected = the form itself), Error, Success, Disabled, Permission (owner-only, admins deliberately excluded even from others' tokens). **Interaction — critical redesign target**: replace the round-tripped real plaintext token with a masked placeholder (e.g., last-4-only) on load, only sending a new value if the user explicitly edits the field; also wrap Disconnect in the app's standard `Confirm` modal for consistency with every other destructive action. **Business Rules**: RULE-SEC-003/004. **Responsive/Accessibility**: standard.

### DESIGN GENERATION PROMPT — Profile
**User**: any role. **Objective**: Keep contact info current, manage password. **IA**: header + read-only Account Info + editable Details form + Change Password form. **Layout**: avatar/name header → 3 stacked sections. **Components**: `Avatar`, `card`, `Field`. **Fields**: read-only (Code/Email/Dept/Designation/Role/Manager/Joining Date), editable (Phone/Address/DOB), password (Current/New/Confirm). **Actions**: Save (profile), Change Password. **States**: Loading, Empty (n/a), Error (field-specific "Incorrect current password"), Success (profile toast; password success auto-reverts after a fixed 4s — redesign target), Disabled, Permission (identical layout for all roles, values differ). **Interaction — new**: replace the fixed 4-second auto-revert on password-change success with a manual dismiss, matching the app's own Toast pattern. **Business Rules**: RULE-EMP-002, RULE-SEC-001/002 (this screen has the strictest password flow in the app — live re-authentication + new≠current — preserve both in any redesign). **Responsive**: `.form-grid-2` at desktop for Details. **Accessibility**: standard.
